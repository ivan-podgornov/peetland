# Инструкции для ИИ-агентов

Peetland — учебный мод для GTA San Andreas, в котором NPC живут своей жизнью и сами планируют свои
дела через HTN. Код на TypeScript собирается в Lua и работает в MoonLoader. Правила проекта описаны
в документации в папке `docs`. Здесь — карта: что где лежит и что читать под задачу. Если правило из
документации противоречит твоим привычкам, права документация.

## Что читать первым

1. [Обзор](./docs/project.md) — что за проект и в каком порядке выбирать между чистотой архитектуры,
   работающим кодом и скоростью.
2. [Архитектура](./docs/architecture/index.md) — что такое чистота архитектуры, слои, внедрение
   зависимостей и жизненный цикл.
3. [Решения](./docs/decisions.md) — записи архитектурных решений. Прочитай те, что касаются задачи.
4. CONTRIBUTING пакета, который меняешь, — его техническая документация, например
   `core/npc/CONTRIBUTING.md`.

Значения терминов — в [глоссарии](./docs/glossary.md).

## Где что лежит

- `toolkit/*` — утилиты без бизнес-логики: HTN, события, геометрия, таймеры.
- `core/*` — бизнес-логика мира: мир, места, NPC, психика, инвентарь, задачи.
- `mod/*` — мод для GTA San Andreas и MoonLoader.
- `docs` — документация на Docusaurus.
- `.github/workflows` — CI.

В пакете: `src` — код и точка входа `src/index.ts`, `__tests__` — тесты, `dev` — помощники для
тестов, которые нужны другим пакетам. `README.md` — продуктовая документация пакета для игрока,
`CONTRIBUTING.md` — техническая (см. [Документация](./docs/process/docs.md)).

## Команды

- `npm install` — поставить зависимости.
- `npm test` — тесты.
- `npm run check:types`, `npm run check:code:all`, `npm run check:deps`,
  `npm run check:formatting:all` — проверка типов, кода, зависимостей и форматирования, как в CI.
- `npm run fix:code:all`, `npm run fix:formatting:all` — исправить код и форматирование.
- `npm run build -w @peetland/mod` — собрать мод.
- `npm start -w @peetland/docs` — запустить сайт документации локально.

## Как работать с задачей

- Неочевидные моменты задачи согласуй с человеком до того, как начинать работу.
- Не указывай в сообщениях коммитов соавторство с агентом.
- На issue, которое тебе дали, открывай один пулл реквест без согласования. Если хочешь разбить
  работу на несколько пулл реквестов, сначала согласуй это.
- Отвечай на каждый комментарий ревью и не резолви их (см. [Ревью](./docs/process/review.md)).
