# @peetland/memory

Память NPC: NPC запоминает факты — тип, детали и момент, когда запомнили, — и вспоминает их по
типу. Как память выглядит для игрока, описано в [README.md](./README.md).

## Факты и их типы

Каждому типу факта соответствуют свои детали: карта «тип → детали» (`MemoryMap`). Факт (`Fact`) —
тип, детали и момент игрового времени, когда его запомнили. Пока факта два: занятое место для
попрошайничества (`placeTaken`) и исследованная мусорка (`binSearched`).

Новый факт — новый ключ в `MemoryMap` со своими деталями. Других фактов память не знает: чтобы
память запоминала больше, добавь ключ в карту.

## Время фактов

Память не ведёт время сама: момент запоминания передаёт вызывающий, обычно код задачи. Задача
берёт время из своего состояния (`NpcState` из `@peetland/npc`) и кладёт в факт слепок
(`getState` у `IReadonlyTime` из `@peetland/timings`) на момент вызова `remember`. Так память
помнит факты в том времени, в котором их запомнила задача. Факт попадает в память через контекст
(см. `NpcContext`).

## Чтение, запоминание и копирование

`IReadonlyMemory` — память только на чтение: `recall(type)` возвращает факты типа в порядке
запоминания, и факты, запомненные после вызова, в возвращённый список не попадают. Такой память
лежит в состоянии NPC. `IMemory` добавляет `remember` — такой памятью задачи пользуются через
контекст (`NpcContext` из `@peetland/npc`).

`clone` возвращает копию памяти, в которую можно писать, как у потребностей и зависимостей:
эффект задачи, который запоминает факт, пишет в копию и кладёт её в новое состояние (см. ADR
«Состояние NPC из живых сущностей»). Факты пока не забываются.
