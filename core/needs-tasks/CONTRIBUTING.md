# @peetland/needs-tasks

Задачи удовлетворения потребностей NPC (`Need` из `@peetland/needs`). Задача «удовлетворить
потребности» — слой потребностей корневой задачи NPC (см.
[корневую задачу](../world/CONTRIBUTING.md#корневая-задача)).

## Задачи

- **Удовлетворить потребности** (`NeedsTask`) — методы — жизненные потребности в порядке
  приоритета: если срочных несколько, первой удовлетворяется та, что выше. Метод подходит, если его
  потребность срочная (`NeedStatus.Urgent`), и планирует задачу удовлетворения этой потребности.
  Если удовлетворить её нечем, планировщик переходит к следующей срочной, а если срочных нет, задачу
  не спланировать, и NPC занимается тем, что ниже в корневой задаче.
- **Утолить голод** (`SatisfyHungerTask`) — восполнить сытость. Методы в порядке приоритета:
  - `eat-from-inventory` — если еда есть в инвентаре, съесть её (`EatTask` из `@peetland/npc-tasks`);
  - `buy-food` — если денег хватает на еду и есть магазин и бомжарня, дойти до ближайшего магазина,
    купить еду по цене из `FOOD_PRICES`, дойти до бомжарни, ближайшей к магазину, и съесть там. У
    дверей магазина NPC не ест, а когда появится поиск пути, будет есть где-нибудь рядом с ним.

  Что из предметов в инвентаре еда, задача спрашивает у классификатора предметов
  (`IItemClassifier`), а что продаётся в магазине, — смотрит по ценам `FOOD_PRICES`. Что съесть или
  купить, выбирает `IFoodChooser` (`FoodChooser`): еду, что восполнит сытость до максимума с
  наименьшим перееданием, а если до максимума не восполнит никакая, — ту, что восполнит больше
  всего. Сколько сытости даёт еда, он спрашивает у потребностей (`getGain`).

Задачи одинаковые для всех типов NPC. Способы удовлетворить потребность — методы её задачи. Если
способ доступен не всем, например рыться в мусорке за едой только бомжу, это решают предусловия
метода по типу NPC из состояния (`state.self.kind`), а не пакет типа NPC.

## Фабрика

`NeedsTaskFactory` реализует `INeedsTaskFactory` и создаёт задачи пакета. Снаружи она получает
геометрию, места, случайные числа и таймер, а фабрику задач NPC (`NpcTaskFactory`), классификатор
предметов (`ItemClassifier`) и выбор еды (`FoodChooser`) по умолчанию собирает сама. На каждый
вызов задача новая: дерево задач не делится между NPC. Наружу пакет показывает фабрику и
`NeedsTask`, а задачи отдельных потребностей создаются только фабрикой.

## Для тестов

Точка входа `@peetland/needs-tasks/dev` даёт:

- мок фабрики (`createMockedNeedsTaskFactory`): задачи, которые не переданы, — заглушки, которые
  всегда можно выполнить;
- зависимости фабрики (`createNeedsTaskFactoryDeps`), в которых мест нет;
- задачу утолить голод (`createSatisfyHungerTask`) и места с магазином `TEST_SHOP` и бомжарней
  `TEST_CAMP` (`createPlacesWithShopAndCamp`);
- мок выбора еды (`createMockedFoodChooser`), который всегда выбирает переданную еду.
