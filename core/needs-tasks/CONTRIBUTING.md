# @peetland/needs-tasks

Задачи удовлетворения потребностей NPC (`Need` из `@peetland/needs`). Задача «удовлетворить
потребности» — слой потребностей корневой задачи NPC (см.
[корневую задачу](../world/CONTRIBUTING.md#корневая-задача)).

## Задачи

- **Удовлетворить потребности** (`NeedsTask`) — методы — жизненные потребности в порядке
  приоритета: если срочных несколько, первой удовлетворяется та, что выше. Метод подходит, если его
  потребность срочная (см. `Needs.isUrgent`), и планирует задачу удовлетворения этой потребности.
  Если удовлетворить её нечем, планировщик переходит к следующей срочной, а если срочных нет, задачу
  не спланировать, и NPC занимается тем, что ниже в корневой задаче.
- **Утолить голод** (`SatisfyHungerTask`) — восполнить сытость. Пока без методов: способов поесть
  нет.

Задачи одинаковые для всех типов NPC. Способы удовлетворить потребность — методы её задачи. Если
способ доступен не всем, например рыться в мусорке за едой только бомжу, это решают предусловия
метода по типу NPC из состояния (`state.self.kind`), а не пакет типа NPC.

## Фабрика

`NeedsTaskFactory` реализует `INeedsTaskFactory` и создаёт задачи пакета. На каждый
вызов задача новая: дерево задач не делится между NPC. Наружу пакет показывает фабрику и
`NeedsTask`, а задачи отдельных потребностей создаются только фабрикой.

## Для тестов

Точка входа `@peetland/needs-tasks/dev` даёт мок фабрики (`createMockedNeedsTaskFactory`):
задачи, которые не переданы, — заглушки, которые всегда можно выполнить.
