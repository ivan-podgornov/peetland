# @peetland/npc

NPC: склеивает свои данные, актора, инвентарь, психику, потребности и HTN-агента, который каждый
тик планирует и исполняет задачи.

## Состояние и контекст

- **Состояние** (`NpcState`) — слепок актора и сами инвентарь, психика, потребности и время,
  доступные только на чтение (`IReadonlyInventory`, `IReadonlyPsyche`, `IReadonlyNeeds`,
  `IReadonlyTime`). С ним HTN-агент планирует задачи. Эффекты задач состояние не меняют: сущность,
  которую нужно поменять, задача клонирует (`clone()`) и кладёт копию в новое состояние. Время
  идёт, и его геттеры могут вернуть разное даже за одно планирование, а копия времени стоит на
  месте, пока её не выставят.
- **Контекст** (`NpcContext`) — живые актор, инвентарь, психика и потребности, которым задачи
  отдают команды.

## Потребности

Начальные значения потребностей лежат в `NpcData.needs`. NPC создаёт потребности фабрикой
`INeedsFactory` со временем, которое знает о мире в момент создания: с него потребности и начинают
падать. Значения потребностей читаются на момент времени из того же состояния:
`state.self.needs.get(need, state.world.time)` (см. [потребности](../needs/CONTRIBUTING.md)).

## Корневая задача

NPC не зависит от задач. Корневую задачу HTN-агента он получает от фабрики `IRootTaskFactory`,
которую объявляет сам и получает в зависимостях. Какую реализацию передать, решает тот, кто
создаёт NPC. Фабрика создаёт каждому NPC своё дерево задач, и между NPC дерево не делится.

Деятельность NPC зависит от его типа, поэтому `npc` объявляет и фабрику деятельности одного типа
`IActivityTaskFactory`. Её реализует пакет с задачами этого типа, например `homeless`, а собирает
корневую задачу из слоёв мир (см. [корневую задачу](../world/CONTRIBUTING.md#корневая-задача)).

## Для тестов

Точка входа `@peetland/npc/dev` даёт builder состояния NPC (`NpcStateBuilder`), контекст NPC
(`createNpcContext`), данные и зависимости NPC (`createNpcData`, `createNpcDeps`) и мок фабрики NPC
(`createMockedNpcFactory`).

`NpcStateBuilder` собирает состояние по шагам: задаёте только то, что важно для теста, а остальное
заполняется незначимыми значениями. NPC стоит в начале координат, инвентарь пуст, потребности
удовлетворены полностью, а в мире полночь первого дня. Психику собирает `PsycheBuilder` из
`@peetland/psyche/dev`: `withPsyche` получает функцию, которой передаётся новый билдер психики, а
то, что она вернёт, ляжет в состояние. `withNeeds` задаёт значения потребностей на момент времени
из состояния.

```ts
import { Item } from '@peetland/inventory';
import { NpcStateBuilder } from '@peetland/npc/dev';
import { Feeling, Trait } from '@peetland/psyche';

const state = new NpcStateBuilder()
  .withPosition(10, 20, 3)
  .withAngle(90)
  .withInventory({ [Item.Money]: 50 })
  .withPsyche((psyche) => psyche.withTrait(Trait.Luck, 80).withFeeling(Feeling.Shame, 30).build())
  .withTime({ day: 1, hours: 20, minutes: 0 })
  .build();
```

Если тесту не важно ни одно поле, хватит готового состояния по умолчанию:

```ts
const state = NpcStateBuilder.default();
```
