# @peetland/world

Мир — точка сборки всего приложения. `World.bigBang` загружает места, собирает зависимости по
умолчанию и создаёт NPC.

## Корневая задача

`RootTask` — жить. Её собирает `RootTaskFactory`, которая реализует `IRootTaskFactory` из
`@peetland/npc`. Методы корневой задачи — слои, перечисленные по приоритету:

1. **Потребности** (`NeedsTask` из `@peetland/needs-tasks`) — то, без чего NPC не может
   жить.
2. **Зависимости** (`AddictionsTask` из `@peetland/addictions-tasks`) — то, без чего NPC жить не
   хочет.
3. **Деятельность** — то, чем NPC занят по своему типу.
4. **Хобби** (`HobbiesTask`) — то, чем NPC занимается для души в свободное от деятельности время.

Планировщик берёт первый слой, в котором есть что планировать, а когда есть, решают предусловия
задач слоя. Пока хобби нет ни у кого, его слой — составная задача без методов.

Слой потребностей — задача удовлетворить потребности (`NeedsTask` из `@peetland/needs-tasks`):
утолить срочный голод, а если голод не горит, но сытость уже не спокойная, — обзавестись жратвой
про запас.

Слой зависимостей — задача удовлетворить зависимости (`AddictionsTask` из
`@peetland/addictions-tasks`): когда тянет выпить, выпить пойло, а если его нет, купить и выпить.

Слой потребностей создаёт фабрика задач удовлетворения `INeedsTaskFactory` из
`@peetland/needs-tasks`, а слой зависимостей — фабрика `IAddictionsTaskFactory` из
`@peetland/addictions-tasks`: эти задачи одинаковые для всех типов NPC, поэтому тип NPC фабрикам не
нужен. Остальные слои создаёт своя фабрика слоя `ILayerTaskFactory` по типу NPC:
`ActivityTaskFactory` и `HobbiesTaskFactory`. Деятельность
`ActivityTaskFactory` по типу NPC берёт у фабрики деятельности этого типа (`IActivityTaskFactory`
из `@peetland/npc`), например у `HomelessActivityTaskFactory` из `@peetland/homeless`. Любую
фабрику слоя и фабрику деятельности типа можно передать в зависимостях вместо фабрики по
умолчанию.

## Связь актора и NPC

Мир создаёт реестр связей «актор ↔ NPC» (`ActorNpcRegistry`) и передаёт его фабрике NPC: каждый NPC
связывает в реестре своего актора с собой (см.
[NPC](../npc/CONTRIBUTING.md#связь-актора-и-npc)). Реестр переводит сущности в обе стороны за
константное время — по NPC находит актора, по актору NPC. Связь живёт, пока жив NPC: при деспавне
реестр её убирает. Акторы без личности (случайные педы) в реестре не появляются. Интерфейс
`IActorNpcRegistry` объявляет `npc` — реализация не должна тянуть `npc` в зависимость от себя.

## Для тестов

Точка входа `@peetland/world/dev` даёт игру и опции мира (`createGame`, `createWorldOptions`) и мок
фабрики корневых задач (`createMockedRootTaskFactory`).
