# Документация

Документация лежит в пакете `docs` и собирается в сайт на Docusaurus. Страницы — обычный Markdown
без MDX прямо в пакете, рядом с его конфигом, диаграммы рисуются на Mermaid. Локально сайт
запускается командой `npm start -w @peetland/docs`.

## Документация пакетов

Документация пакета лежит в самом пакете, в двух файлах:

- **`README.md` — продуктовая.** Что пакет даёт игроку: что делает NPC, как он себя ведёт и от чего
  это зависит. Пишется для игрока, человеческим языком и без имён из кода. Если пакету нечего
  рассказать игроку, как пакетам toolkit, README короткий: что это за пакет и ссылка на
  CONTRIBUTING.
- **`CONTRIBUTING.md` — техническая.** Как пакет устроен и как с ним работать: классы, интерфейсы,
  зависимости, помощники для тестов. Длинные темы выносятся в папку `docs` пакета.

### Техническая документация на сайте

Раздел «Пакеты» читает CONTRIBUTING и папку `docs` прямо из пакетов, без копий. Относительные
ссылки в них должны вести на Markdown внутри пакета, иначе сборка сайта упадёт на битой ссылке.

### Продуктовая документация на сайте

Продуктовый README показывается на сайте не в «Пакетах», а в разделе для игрока, например в «NPC».
Чтобы README попал на сайт:

1. Прописать страницу и README пакета в `PRODUCT_PAGES` в `docs/docusaurus.config.ts`, например
   `'npc/homeless.md': 'core/homeless/README.md'`.
2. Добавить путь страницы в `.gitignore`: сайт при каждом запуске копирует README на место
   страницы, и копия не хранится в git.
3. Поставить страницу в сайдбар `docs/sidebars.ts`.

В продуктовом README не должно быть относительных ссылок: копия лежит в другом месте, и ссылки из
неё сломаются. А ссылки на продуктовый README из технической документации работают: на сайте они
ведут на его страницу, например ссылка на `./README.md` из CONTRIBUTING бомжа ведёт на страницу
«Бомж-алкаш».
