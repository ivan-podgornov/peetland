# Планирование

## Milestone

Milestone — большая цель, к которой идут несколько issue, например «Документация». Issue из
milestone вместе дают эту цель, а milestone закрывается, когда закрыты все его issue. Issue без
milestone — это нормально: не каждая задача относится к большой цели.

## Issue и лейблы

Issue заводится только через шаблон: фича, баг, рефакторинг, документация или инфраструктура.
Шаблон сам ставит лейбл типа, а лейблы области автор ставит руками.

У issue ровно один лейбл типа. Он совпадает с типом коммита по этой задаче:

| Лейбл            | Задача         |
| ---------------- | -------------- |
| `type: feat`     | фича           |
| `type: fix`      | баг            |
| `type: refactor` | рефакторинг    |
| `type: docs`     | документация   |
| `type: ci`       | инфраструктура |

Лейблов области один или несколько — по пакетам, которые затрагивает задача:

| Лейбл           | Пакеты                                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------ |
| `area: htn`     | `htn`                                                                                                        |
| `area: events`  | `events`                                                                                                     |
| `area: toolkit` | остальные пакеты toolkit: `geometry`, `logger`, `random`, `repository`, `timings`                            |
| `area: game`    | `game`                                                                                                       |
| `area: world`   | `world`, `places`                                                                                            |
| `area: npc`     | `npc`, `npc-tasks`, `psyche`, `homeless`, `inventory`, `actor-command`, `animation-manager`, `virtual-actor` |
| `area: mod`     | `gta-sa`, `moonloader`, `mod`                                                                                |
| `area: ci`      | workflow и конфиги сборки в корне репозитория                                                                |

Лейблы типа и области ставятся только на issue, на пулл реквесты — нет.

## Связи между issue

Если задачу нельзя начать, пока не сделана другая, это отмечается связью GitHub «Blocked by», а не
текстом в описании. Так зависимость видна в обоих issue и пропадает сама, когда блокирующую задачу
закрывают.

## Когда писать ADR

Если в задаче принимается новое решение, причину которого не видно из кода, автор решает, нужна ли
для него запись архитектурного решения. Правила и шаблон записи — в разделе
[Решения](../decisions.md).
