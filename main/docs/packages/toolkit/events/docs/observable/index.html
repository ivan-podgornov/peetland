Observable

Реализация Observable — веб-стандарта для работы с потоками событий. Пакет стремится как можно точнее повторить спецификацию: те же названия, те же правила подписки и отписки, тот же порядок вызовов.

Как пользоваться Observable, читайте в документации MDN:

  • Observable — справочник;
  • Using observables — подписка и отписка;
  • Creating custom observables — создание своих источников.

В пакете также есть AbortController, AbortSignal и EventTarget, на которых строится отписка.

import { AbortController, Observable } from '@toolkit/events';

const values = new Observable<number>((subscriber) => {
  subscriber.next(1);
  subscriber.complete();
});

const controller = new AbortController();

values.subscribe((value) => console.log(value), { signal: controller.signal });

Отличия от спецификации​

reportError​

Исключения, которые некому обработать, попадают в глобальный reportError, как в браузере. Он вызывается, когда:

  • источник выдал subscriber.error(...), а у наблюдателя нет обработчика error;
  • executor выбросил исключение. Оно превращается в вызов subscriber.error(...), поэтому наблюдатель с обработчиком error получит ошибку в него, а без обработчика ошибка уйдёт в reportError;
  • выбросил исключение любой из обработчиков наблюдателя (next, error, complete). Такое исключение не закрывает подписку и не мешает остальным наблюдателям;
  • выбросил исключение teardown-колбэк или колбэк abort в inspect.
const values = new Observable<number>((subscriber) => {
  subscriber.error(new Error('источник сломался'));
});

values.subscribe({ next: () => {} }); // reportError(Error: источник сломался)

Если у нескольких наблюдателей нет обработчика error, reportError вызывается отдельно для каждого.

reportError есть не во всех окружениях, поэтому его объявляет то окружение, где выполняется код: мод печатает ошибку в лог MoonLoader, а в тестах это мок из vitest.setup.ts.

Ограниченная поддержка​

Observable.from пока принимает только Observable, массивы и промисы. Остальные итерируемые и асинхронно итерируемые значения (строки, Set, генераторы) приводят к TypeError.

Из операторов пока реализованы только switchMap и inspect. Остальные (map, filter и другие) будут добавляться по мере необходимости.
