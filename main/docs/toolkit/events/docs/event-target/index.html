EventTarget

Типизированный эмиттер событий. Если вы работали с EventTarget в браузере, API покажется знакомым: addEventListener, removeEventListener, dispatchEvent. Главное отличие в том, что названия событий и данные, которые с ними передаются, описываются типами и проверяются компилятором.

Быстрый старт​

Сначала опишите события: ключ - название события, значение - тип данных, которые с ним передаются.

import { EventTarget } from '@peetland/events';

type Events = {
  npcDied: [id: number];
};

const target = new EventTarget<Events>();

Назначьте обработчик и породите событие:

function onNpcDied(id: number) {
  console.log(`NPC ${id} умер`);
}

target.addEventListener('npcDied', onNpcDied);
target.dispatchEvent('npcDied', 42); // NPC 42 умер

Когда обработчик больше не нужен, снимите его:

target.removeEventListener('npcDied', onNpcDied);

Компилятор проверит и название события, и тип данных. Опечатка в названии или строка вместо числа не пройдут.

События с данными и без них​

Если у события есть данные, укажите их тип. Второй параметр dispatchEvent тогда обязателен:

type Events = {
  npcDied: [id: number];
};

target.dispatchEvent('npcDied', 42); // ok
target.dispatchEvent('npcDied'); // ошибка: данные обязательны

Если данных нет, укажите пустой кортеж. Тогда второй параметр не нужен, а обработчик не принимает аргументов:

type Events = {
  tick: [];
};

target.addEventListener('tick', () => console.log('тик'));
target.dispatchEvent('tick');

Чтобы передать несколько значений, объедините их в объект:

type Events = {
  npcMoved: [{ id: number; x: number; y: number }];
};

target.dispatchEvent('npcMoved', { id: 1, x: 10, y: 20 });

Снятие обработчиков​

removeEventListener​

Чтобы снять обработчик, removeEventListener нужно передать ту же функцию, что и при назначении. Поэтому, если обработчик придётся снимать, сохраните его в переменную или объявите функцией. Анонимную стрелочную функцию снять не получится:

target.addEventListener('tick', () => console.log('тик')); // снять нельзя

const onTick = () => console.log('тик');
target.addEventListener('tick', onTick);
target.removeEventListener('tick', onTick); // можно

Если обработчика нет, removeEventListener ничего не делает и не выбрасывает ошибок.

Параметр signal​

Ещё один способ снять сигнал - передать в addEventListener опцию signal со значением AbortSignal. Если такой сигнал перейдёт в состояние aborted, обработчик будет снят:

const controller = new AbortController();
target.addEventListener('tick', onTick, { signal: controller.signal });
controller.abort(); // обработчик снят и больше не будет вызван

Если обработчик уже был снят другим способом, вызов abort ни на что не повлияет.

Обработчик на один раз​

Третьим параметром addEventListener принимает опции. Опция once делает обработчик одноразовым: он сработает при ближайшем порождении события и после этого снимется сам.

target.addEventListener('npcDied', onNpcDied, { once: true });

target.dispatchEvent('npcDied', 1); // NPC 1 умер
target.dispatchEvent('npcDied', 2); // ничего не произойдёт

Такой обработчик снимается до вызова, а не после. Поэтому, если внутри него снова породить то же событие, повторно он не вызовется. Если обработчик выбросит исключение, он всё равно будет снят.

Пока одноразовый обработчик не сработал, его можно снять вручную тем же removeEventListener и той же функцией:

target.addEventListener('npcDied', onNpcDied, { once: true });
target.removeEventListener('npcDied', onNpcDied);
target.dispatchEvent('npcDied', 1); // ничего не произойдёт

Повторное назначение​

Обработчик определяется парой «название события + функция». Если назначить ту же функцию на то же событие второй раз, второе назначение будет проигнорировано:

target.addEventListener('tick', onTick);
target.addEventListener('tick', onTick);

target.dispatchEvent('tick'); // onTick вызовется один раз
target.removeEventListener('tick', onTick); // и одного снятия достаточно

Опции в эту пару не входят. Если функция уже назначена, то повторное назначение с другими опциями ничего не изменит, и останутся опции первого назначения:

target.addEventListener('tick', onTick); // обычный обработчик
target.addEventListener('tick', onTick, { once: true }); // игнорируется

target.dispatchEvent('tick');
target.dispatchEvent('tick'); // onTick вызвался оба раза

А вот одну и ту же функцию можно назначить на несколько разных событий, и они не влияют друг на друга. Если одноразовый обработчик уже сработал, он снят, и назначить его снова можно с любыми опциями.

Изменение обработчиков во время события​

Обработчики можно назначать и снимать прямо внутри других обработчиков. Правила такие.

Обработчик, назначенный во время порождения события, в текущем порождении не вызывается. Он начнёт работать со следующего:

target.addEventListener('tick', () => {
  target.addEventListener('tick', onTick);
});

target.dispatchEvent('tick'); // onTick не вызван
target.dispatchEvent('tick'); // onTick вызван

Обработчик, снятый до того, как до него дошла очередь, не вызывается, даже если событие уже порождено:

target.addEventListener('tick', () => {
  target.removeEventListener('tick', onTick);
});
target.addEventListener('tick', onTick);

target.dispatchEvent('tick'); // onTick не вызван

Обработчики вызываются в том порядке, в котором были назначены.

Обработка ошибок​

Исключение в одном обработчике не должно ломать остальные, поэтому эмиттер перехватывает ошибки сам.

  • dispatchEvent не выбрасывает исключения наружу, даже если обработчик упал.
  • Остальные обработчики события продолжают вызываться.
  • Упавший обработчик остаётся назначенным и вызовется при следующем порождении события (кроме одноразового: он снимается в любом случае).

Перехваченное исключение уходит в глобальный reportError, как в браузере:

const target = new EventTarget<Events>();

target.addEventListener('tick', () => {
  throw new Error('boom');
});

target.dispatchEvent('tick'); // reportError(Error: boom), исключение наружу не вылетит

Если упало несколько обработчиков, reportError вызывается для каждого исключения отдельно, в порядке вызова обработчиков.
